# План улучшения Developer Experience (DX) для плагинов Notehub.md

Проанализировав текущую структуру проекта, CLI и тестовый плагин `khton.dock-bar`, я составил список необходимых улучшений для того, чтобы создание плагинов стало таким же простым и гибким, как в Obsidian.

## 1. 🚨 Критическая ошибка сборки (React JSX Runtime)

**Проблема:**
Новые плагины, созданные через `nhp create`, по умолчанию используют современную трансформацию JSX (`react/jsx-runtime`). Однако, среда выполнения приложения (browser/webview) не предоставляет модуль `react/jsx-runtime` через SystemJS, а предоставляет только классический `react`. Это приводит к падению плагина при загрузке с ошибкой `Unable to resolve bare specifier 'react/jsx-runtime'`.

**Решение (порядок приоритета):**
1.  **Исправить шаблон CLI (Быстро):** Изменить `generateTsConfig` в `packages/cli/src/commands/create.ts`, чтобы поле `jsx` по умолчанию было `"react"` (Classic), а не `"react-jsx"`. Также добавить `import React from 'react'` в шаблон компонента.
2.  **Обновить Core (Правильно):** Добавить алиас `react/jsx-runtime` -> `react/jsx-runtime.js` (из пакета `react`) в карту импортов SystemJS в `packages/system/synapse`. Это позволит использовать современный синтаксис без импорта React.

## 2. 🧩 Система Зон (Layout & Zones)

**Проблема:**
Плагин `dock-bar` показал, что механизм `zone:register` работает и позволяет внедрять UI. Однако:
-   Нет документации, какие зоны существуют (мы гадали между `editor`, `status-bar`, `editor-footer`).
-   Нет типизации для зон в `@notehub/api`.

**Решение:**
-   **Документация:** Создать визуальную схему макета с названиями зон.
-   **Inspector:** Добавить команду разработчика "Show Zone IDs", которая подсвечивает все активные зоны и их ID прямо в интерфейсе.
-   **Типизация:** Добавить `ZoneId` enum в `contract.d.ts` (например, `'sidebar-left' | 'editor-footer' | 'ribbon'`).

## 3. 📝 API Редактора

**Проблема:**
Для реализации кнопки "Bold" нам пришлось использовать команду `command:execute`. В публичном контракте (`NotehubApiMap`) отсутствуют методы для прямой манипуляции текстом.

**Решение:**
Добавить в `nh.features.editor` (и проксировать в API) методы:
-   `editor:get-selection(): string`
-   `editor:replace-selection(text: string): void`
-   `editor:insert-text(text: string, cursorOffset?: number): void`
-   `editor:get-cursor-position(): { line: number, ch: number }`

## 4. 🛠 Инструментарий (CLI)

**Проблема:**
Команда `nhp build` жестко задает `external` зависимости. Если плагин захочет использовать библиотеку, которая не входит в Core (например, `lodash` или `chart.js`), она может не собраться корректно в SystemJS формат без дополнительной настройки.

**Решение:**
-   Разрешить пользователю переопределять или расширять конфигурацию Vite через файл `vite.config.ts` в корне плагина, который `nhp build` будет считывать и мержить с дефолтным конфигом.

---

**Итог:**
Чтобы достичь "бесконечной гибкости", нужно:
1.  Устранить барьер входа (фикc JSX).
2.  Дать разработчикам карту "куда можно встроиться" (Zones).
3.  Дать инструменты для работы с контентом (Editor API).
