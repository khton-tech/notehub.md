# Отчет: Глобальный рефакторинг критических багов ядра (Core App)

В ходе детального аудита кодовой базы основного приложения (`packages/` и `apps/`) с игнорированием сторонних плагинов (`custom/`), а также после запуска полного набора тестов (`pnpm -r test`), были выявлены следующие два **критических бага**, напрямую влияющих на стабильность, потребление памяти и жизненный цикл плагинов.

## 1. Утечка памяти и дублирование RPC-вызовов в TitleBar
**Локация:** `packages/plugins/system/titlebar/src/logic/TitleBarController.ts`
**Проблема:** В методе `init()` контроллера оконного заголовка запускается `setInterval`, который каждые 500мс проверяет статус `editor:is-dirty`. Однако перед запуском нового интервала не происходит очистка предыдущего (отсутствует `clearInterval`).
**Критичность:** Поскольку `init()` может вызываться неоднократно (например, при React Strict Mode, Hot Module Replacement или повторном монтировании компонента при смене лейаута), каждый такой вызов порождает новый "бесконечный" интервал. Это приводит к экспоненциальному росту количества RPC-опросов по шине данных и серьезной утечке памяти приложения.
**Решение:** В метод `init()` необходимо добавить синхронную проверку и сброс интервала: `if (this.dirtyCheckInterval) clearInterval(this.dirtyCheckInterval);` перед его переназначением.

## 2. Состояние "Зомби" и Race Condition при выгрузке плагинов (Synapse)
**Локация:** `packages/plugins/system/synapse/src/logic/PluginContextImpl.ts`
**Проблема:** В классе `PluginContextImpl`, который отвечает за "песочницу" и жизненный цикл всех плагинов, есть метод `async cleanup()`. При его вызове флаг `this.disposed = true` устанавливается только *в самом конце* метода, после завершения асинхронного `await Promise.allSettled(asyncOps);`.
**Критичность:** Это вызывает катастрофический Race Condition (состояние гонки). Поскольку метод асинхронный, он возвращает управление в Event Loop до того, как `this.disposed` станет `true`. В это окно времени плагин формально еще "жив" и может продолжать регистрировать API, подписываться на события и слушать хуки (приводя к зомби-процессам и утечкам), хотя системно он уже находится в стадии выгрузки. Именно этот архитектурный баг приводит к падению 7-ми юнит-тестов (AssertionError) при выполнении тестового пайплайна в `packages/plugins/system/synapse`.
**Решение:** Флаг `this.disposed = true;` должен быть установлен синхронно в самой первой строке метода `cleanup()`, чтобы моментально заблокировать любые новые взаимодействия выгружаемого плагина с ядром.

---
*Остальная инфраструктура ядра (`packages`, `apps`) стабильна: полная сборка `pnpm -r build` проходит без ошибок TypeScript, и скрытых падений в catch-блоках файловой системы не обнаружено. Рекомендуется приступить к немедленному устранению описанных двух проблем.*
