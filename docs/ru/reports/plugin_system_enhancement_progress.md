# Отчет о Реализации Улучшений Системы Плагинов Notehub.md

**Дата:** 9 февраля 2026 г.
**Статус:** Фазы 1-4 завершены ✅, Фазы 5-6 ожидают выполнения ⏳

В данном отчете представлен подробный обзор выполненных работ по модернизации архитектуры системы плагинов Notehub.md, а также план дальнейших действий. Целью данных изменений является повышение гибкости, расширяемости и надежности системы плагинов.

## 1. Обзор Выполненных Работ (Фазы 1-4)

Мы успешно завершили реализацию ключевых архитектурных компонентов, необходимых для поддержки продвинутых сценариев использования плагинов.

### ✅ Фаза 1: Quick Wins (Быстрые Победы)

Целью этой фазы было устранение критических блокирующих проблем и предоставление базовых API для работы с редактором и UI.

#### 1.1. Исправление JSX Runtime в SystemJS
**Проблема:** Внешние плагины, использующие React JSX, падали с ошибкой `Unable to resolve bare specifier 'react/jsx-runtime'`.
**Решение:**
- В `ScopeInitializer.ts` добавлена ручная регистрация модулей `react/jsx-runtime` и `react/jsx-dev-runtime` в SystemJS registry.
- Обновлен Import Map для корректного маппинга импортов.
**Результат:** Плагины могут использовать современный JSX синтаксис без дополнительных настроек бандлера.

#### 1.2. Расширение Editor API (13 новых методов)
**Проблема:** Отсутствие стандартного способа взаимодействия с содержимым редактора (текст, курсор, выделение).
**Решение:** В `contract.ts` и `EditorController` добавлены методы:
- **Текст:** `editor:get-content`, `editor:set-content`, `editor:insert-text`, `editor:get-line`, `editor:get-line-count`.
- **Курсор:** `editor:get-cursor`, `editor:set-cursor`.
- **Выделение:** `editor:get-selection`, `editor:replace-selection`, `editor:get-selection-range`, `editor:set-selection-range`.
- **Unsafe:** `editor:unsafe_get-view` (доступ к инстансу CodeMirror EditorView).

#### 1.3. Стабилизация UI Зон
**Проблема:** Невозможность надежно найти DOM-элементы зон (sidebar, ribbon) для инъекции контента через React Portals или Vanilla JS.
**Решение:**
- Введен TypeScript enum `ZoneId` (`contract.ts`) для типизации идентификаторов зон.
- Обновлен `LayoutManager`: все зоны теперь рендерятся с атрибутом `data-nh-zone="<zone-id>"`.

### ✅ Фаза 2: Escape Hatches (Аварийные Выходы)

Предоставление инструментов для обхода ограничений "безопасного" API для продвинутых плагинов.

#### 2.1. Unsafe Context & Hooks
**Решение:** Расширен `PluginContext` (интерфейс, передаваемый в плагин).
- Добавлено свойство `ctx.unsafe`.
- Реализован метод `ctx.unsafe.hook(method, position, handler)`, позволяющий перехватывать вызовы любых API методов.
- Поддержка `before`, `after` и `around` перехватчиков.
- Автоматическая очистка хуков при выгрузке плагина в `PluginContextImpl`.

#### 2.2. DOM Helpers
**Решение:** Добавлен API метод `dom:wait-for-zone(zoneId, timeout)`.
- Реализован с использованием `MutationObserver` для эффективного ожидания появления элемента в DOM, что критично для асинхронной загрузки React-компонентов.

#### 2.3. Генерация событий из плагинов
**Решение:** В `PluginContext` добавлен метод `emit(event, payload)`, позволяющий плагинам отправлять события в общую шину `EventBus`.

### ✅ Фаза 3: Динамический API Контракт

Обеспечение возможности плагинам расширять API и взаимодействовать друг с другом.

#### 3.1. Улучшенная Система Хуков
**Новые возможности в `ApiBus`:**
- **Приоритеты (`priority`):** Возможность задавать порядок выполнения хуков (число, по умолчанию 0, выше = раньше).
- **Условия (`condition`):** Хук выполняется, только если функция-предикат возвращает `true`.
- **Интерфейс `HookOptions`:**
  ```typescript
  interface HookOptions {
      priority?: number;
      condition?: (args: unknown[]) => boolean;
  }
  ```

#### 3.2. API Discovery (Интроспекция)
**Решение:** Добавлены встроенные API методы для исследования доступных функций системы:
- `api:list` — получить список имен всех зарегистрированных методов.
- `api:has(name)` — проверить наличие метода.
- `api:info(name)` — получить детальную информацию (количество хуков и их типы).
- `api:list-with-metadata` — полный список с метаданными.

Это позволяет плагинам адаптироваться к окружению и проверять наличие зависимостей (других плагинов).

### ✅ Фаза 4: EventBus 2.0

Переработка системы событий для поддержки сложных сценариев взаимодействия.

#### 4.1. Отмена Событий (Cancelable Events)
**Решение:** В обработчики событий теперь передается второй аргумент — `context: EventContext`.
- `context.preventDefault()` — помечает событие как "отмененное" (`defaultPrevented = true`). Эмитент события может проверить этот флаг и не выполнять действие по умолчанию (например, закрытие приложения).
- `context.stopPropagation()` — немедленно останавливает дальнейший вызов обработчиков.

#### 4.2. Приоритеты Обработчиков
**Решение:** Метод `on` теперь принимает `SubscribeOptions`.
- `priority`: обработчики с более высоким приоритетом выполняются первыми.

#### 4.3. Последовательное Выполнение
**Изменение:** `EventBus.emit` теперь выполняет обработчики **последовательно** (sequentially), ожидая завершения асинхронных обработчиков, в порядке убывания приоритета. Это гарантирует предсказуемость порядка выполнения и корректную работу отмены событий.

## 2. Планируемые Работы (Фазы 5-6)

Следующие этапы сосредоточены на приведении всей кодовой базы к новой архитектуре и улучшении опыта разработки.

### ⏳ Фаза 5: Унификация (Приоритет: Высокий)

Самый трудоемкий этап. В данный момент в системе существует два способа написания плагинов: старый (`IPlugin`) и новый (`PluginContext`). Системные плагины используют старый подход, внешние — новый.

**Задачи:**
1.  **Расширение `PluginContext` для системных нужд:** Добавить в контекст методы, необходимые внутренним плагинам, но, возможно, скрытые или ограниченные для внешних.
2.  **Миграция 14 системных плагинов:**
    - `logger`, `config-manager`, `state-manager`
    - `fs-manager`, `context-manager`, `layout-manager`
    - `editor`, `synapse` (loader внешних плагинов)
    - Драйверы файловой системы (`fs-driver-*`)
    - `bootloader`, `keymap`, `command-manager`, `titlebar`
3.  **Refactoring:** Переписать код этих плагинов так, чтобы они принимали `PluginContext` в методе `load`, вместо прямого доступа к `app`.

**Цель:** Единый архитектурный стиль, упрощение тестирования и поддержки. Вся логика приложения станет набором равноправных модулей.

### ⏳ Фаза 6: Developer Experience (Приоритет: Средний)

Создание инструментов для удобной разработки и отладки плагинов.

**Задачи:**
1.  **Developer Tools Plugin:**
    - Визуализация зон (`dev:show-zones`).
    - Просмотрщик зарегистрированных API и событий в UI.
    - Статистика загруженных плагинов.
2.  **CLI Improvements:** Доработка `nhp` (Notehub Plugin CLI) для поддержки конфигов сборки (`vite.config.ts`), шаблонов плагинов.

## 3. Технические Детали и Примеры Использования

### Использование новых возможностей EventBus

```typescript
// Подписка с высоким приоритетом и возможностью отмены
ctx.events.on('app:quit', async (payload, context) => {
    const hasUnsavedChanges = await checkUnsavedChanges();
    if (hasUnsavedChanges) {
        // Отменяем стандартное действие (выход)
        context.preventDefault();
        console.log('Exit cancelled by plugin');
    }
}, { priority: 100 });
```

### Использование условных хуков API

```typescript
// Перехват записи только Markdown файлов
ctx.unsafe.hook('fs:write-text-file', 'before', (args) => {
    const [path, content] = args;
    // Логика препроцессинга...
    console.log('Saving MD file:', path);
}, {
    // Условие выполнения
    condition: (args) => String(args[0]).endsWith('.md')
});
```

### Динамическое обнаружение API

```typescript
// Проверка наличия API перед вызовом
if (await ctx.invokeApi('api:has', 'my-plugin:custom-feature')) {
    await ctx.invokeApi('my-plugin:custom-feature', { data: 123 });
} else {
    console.warn('Custom feature API not available');
}
```
