# UI Redesign Proposal — notehub.md
**Дата:** 2026-02-19
**Роль:** Ведущий веб-дизайнер
**Статус:** Предложение к пересмотру дизайна

---

## Резюме

После глубокого анализа кодовой базы выявлено, что текущий UI является грамотно реализованным, но **вторичным** продуктом — визуальным клоном Obsidian + VS Code с элементами glassmorphism. Приложение технически состоятельно, однако лишено собственной личности, эмоционального вовлечения и интуитивных паттернов взаимодействия, характерных для современных продуктивных инструментов (Linear, Notion, Arc). Данный отчёт не предлагает косметических правок — он предлагает **пересмотр дизайн-парадигмы**.

## 2. Критический анализ текущего UI

### 2.1 Глобальная проблема: отсутствие идентичности

Текущий дизайн складывается из следующих решений:
- Rich Black фон (`#0A0A0A`) — **как у Obsidian**
- Ribbon вертикальный слева — **как у Obsidian**
- EXPLORER в uppercase tracking-wider — **как у VS Code**
- Sidebar с tab-контентом настроек — **как у VS Code**
- Floating glassmorphism panels — **как у Arc Browser**

Результат: узнаваемо, но чужое. Пользователь не чувствует уникального продукта.

**Приговор**: Дизайн-система должна быть переосмыслена с точки зрения own identity, а не композиции чужих референсов.

---

### 2.2 Welcome Screen — первое впечатление провалено

**Файлы:** `WelcomeLayout.tsx`, `VaultActions.tsx`, `VaultList.tsx`

**Текущее состояние:**
```
[Боковая панель: Recent Vaults] | [Центр: Логотип + 2 кнопки]
```

**Проблемы:**
1. **Нет эмоционального крюка.** Tagline "Gather your data together" — это функциональное описание, а не приглашение. Первый экран не отвечает на вопрос "Зачем мне это нужно прямо сейчас?"
2. **Список вóлтов — плоский.** Каждый vault — строка с иконкой папки. Нет превью содержимого, нет даты последнего открытия отображаемой визуально, нет разделения по "pinned/recent".
3. **Кнопки занимают max-w-[300px]** в центре огромного пустого экрана — гигантский void слева (в списке вольтов) и справа от кнопок.
4. **Новый пользователь дезориентирован.** Нет onboarding flow, нет подсказок что такое "vault", нет демонстрации ценности.
5. **Удаление vault из истории не реализовано** (`// TODO: Implement vault deletion from history`), кнопка X показывается пользователю, но ничего не делает.

### 2.3 Editor Layout — фрагментация без ритма

**Файл:** `EditorLayout.tsx`

**Текущее состояние (desktop grid):**
```
ribbon (3.5rem) | gap(16px) | sidebar (250px) | gap(16px) | main | gap(16px) | status
```

**Проблемы:**
1. **Четыре "плавающих" панели создают визуальный шум.** Gap в 16px между всеми элементами разбивает интерфейс на острова. Для приложения, которое должно создавать ощущение "монолитного рабочего пространства", это контрпродуктивно.
2. **Ribbon шириной 56px — слишком узок.** Иконки кажутся втиснутыми. Нет подписей, нет tooltips (только HTML `title` атрибут — не работает на тач-устройствах).
3. **Status bar — лишний элемент.** Небольшая панель снизу занимает место, но её содержимое непонятно пользователю. Зачем она отдельным "floating panel"?
4. **Нет breadcrumb навигации.** Пользователь не видит полный путь к текущему файлу.
5. **Нет разделения editor / preview.** Отсутствует split view.
6. **Нет контекстных действий на уровне layout.** Хочешь создать файл? Нужно идти в Explorer. Хочешь вызвать команду? Нет видимого CTA.

---

### 2.4 File Tree — функционально, но не дружелюбно

**Файлы:** `FileTree.tsx`, `NodeRow.tsx`

**Проблемы:**
1. **"EXPLORER" в uppercase** — прямая копия VS Code. Для note-taking приложения это неверная метафора. Пользователь исследует не "файлы", а "идеи и заметки".
2. **Строка поиска всегда видна.** `px-2 py-1.5` занимает ~36px постоянно, даже когда пользователь никогда не использует поиск. Это должен быть collapsible элемент или icon-кнопка.
3. **Высота строки 24px — очень плотно** для приложения заметок. В VS Code 22px оправдано — там работают с кодом и структура плоская. В notes-приложении дерево глубокое, элементы нужно различать быстро.
4. **Empty state — только italic текст.** `"Empty vault"` — нет никакого призыва к действию, нет иллюстрации, нет помощи.
5. **Иконки файлов и папок — монохромные.** `text-[var(--nh-text-muted)]` — все файлы выглядят одинаково. Невозможно отличить `.md` от других типов файлов визуально.
6. **Контекстное меню при hover** — кнопка "+" открывает dropdown. Но после нажатия меню появляется неожиданно, без анимации позиционирования. Dropdown рендерится через `absolute`, а не portal — может обрезаться.

---

### 2.5 TabBar — почти невидима

**Файл:** `tabbar.css`, `TabBar.tsx`

**Проблемы:**
1. **Активный таб почти неотличим.** `bg-secondary (#1A1A1A)` vs `transparent` — разница в 6 единицах яркости. В реальном интерфейсе это сливается.
2. **Нет индикатора несохранённых изменений.** Нет точки или звёздочки `*` у изменённых файлов.
3. **При 0 табов компонент возвращает `null`** — визуально исчезает "шапка" редактора. Лучше показывать placeholder с CTA "Open a file".
4. **Нет кнопки "новый таб" или "+"**  — обнаружимость ограничена.
5. **FileText иконка у каждого таба** — все иконки одинаковые, нет семантики типа файла.

---

### 2.6 Context Menu — слишком агрессивный hover

**Файл:** `ContextMenu.tsx`

**Проблема:**
```css
.nh-context-menu-item:hover {
    background: var(--nh-accent-primary, #6b5ce7); /* Solid purple fill */
    color: #ffffff;
}
```

Это паттерн из 2015 года. Современные context menus (macOS, Linear, Notion) используют **subtle** hover: `rgba(accent, 0.12)` с сохранением текущего цвета текста или лёгким его осветлением. Solid purple fill при hover создаёт агрессивный, "кричащий" эффект, который отвлекает внимание.

---

### 2.7 Floating Toolbar — статичный и не контекстуальный

**Файл:** `FloatingToolbar.tsx`

**Проблемы:**
1. **Нет активных состояний кнопок.** Если выделен жирный текст — кнопка Bold не подсвечена. Пользователь не понимает текущее форматирование.
2. **Группировка захардкожена** (`{index === 4 && <div style={styles.separator} />}`) — неправильный подход. Группировка должна быть декларативной.
3. **Только 8 операций.** Нет Strikethrough, Highlight, Inline Math, Table.
4. **Toolbar появляется выше выделения**, но не имеет "хвостика" (caret) как в Notion — пользователь теряет контекст.
5. **Hover state** через `useState` в компоненте вместо CSS `:hover` — лишняя перерисовка.

---

### 2.8 Settings Modal — скучно и стандартно

**Файл:** `SettingsModal.tsx`

**Проблемы:**
1. **Sidebar + content** — самый избитый паттерн. Работает, но не memorable.
2. **Нет поиска по настройкам.** При 10+ табах (с плагинами) найти нужную настройку трудно.
3. **Нет preview изменений.** Смена темы не показывает live preview рядом с выбором.
4. **800×600px фиксированный размер** — на мониторах 1440p выглядит маленьким; на 1024px может не влезть.
5. **DynamicIcon возвращает `?`** если иконка не найдена — видимый баг в UI.

---

### 2.9 Цветовая система — монотонная

**Файл:** `ThemeManager/index.ts`

Текущая Deep Space палитра:
- Фоны: `#0A0A0A → #101010 → #141414 → #1A1A1A → #1E1E1E`
- Разница между слоями: 6–10 единиц яркости в hex

**Проблемы:**
1. **Пять оттенков почти чёрного** — без calibrated contrast это превращается в "серая каша". На некачественных мониторах слои неразличимы.
2. **Accent #7c3aed** — единственный яркий цвет. Нет поддерживающей цветовой роли (success, info, warning используются только в callouts).
3. **Нет цветовой семантики в навигации.** Активный элемент = accent цвет, disabled = opacity 0.4. Нет intermediate states.
4. **`panel-glow`: `inset 0 0 0 1px rgba(255,255,255,0.05)`** — 5% непрозрачности. На OLED мониторах этот эффект вообще не виден.

## 3. Новая Дизайн-Парадигма: "Focused Space"

### 3.1 Философия

Отказаться от метафоры "инструмент разработчика" (VS Code) в пользу метафоры **"личное мыслительное пространство"**. Дизайн должен:

- **Убирать себя из фокуса** — когда пишешь, ничто не должно отвлекать
- **Появляться когда нужен** — панели, инструменты, подсказки появляются в контексте действий
- **Создавать ощущение тепла** — холодный технологический дизайн заменить на тёплые, органические детали
- **Демонстрировать ценность** — каждый экран должен показывать, что приложение делает для пользователя, а не что пользователь должен делать с приложением

### 3.2 Новая визуальная система

#### Цветовая палитра (Deep Space 2.0)

```
Фон главный:    #0D0D10  → чуть теплее, с едва заметным синим оттенком
Фон поверхность:#13131A  → +7 от main, readable contrast
Фон secondary:  #1A1A25  → +12, заметная глубина
Фон hover:      #20202E  → явный, не сливается

Accent Purple:  #8B5CF6  → чуть светлее (violet-500), не такой тяжёлый
Accent Teal:    #06B6D4  → поддерживающий цвет для success/info
Accent Amber:   #F59E0B  → для предупреждений, активных состояний

Текст primary:  #F0F0F8  → теплее, не чисто белый
Текст secondary:#A0A0BC  → с лёгким purple tint
Текст muted:    #606080  → с лёгким blue tint
```

Ключевое изменение: **добавить temperature** — все цвета имеют лёгкий голубовато-фиолетовый подтон. Это создаёт единство палитры и ощущение "ночного неба", а не "угля".

#### Типографика

```
Heading: "Geist" (Vercel) или "Cal Sans" — геометрический, современный
Body:    "Inter" (текущий) — остаётся
Mono:    "JetBrains Mono" (текущий) — остаётся
```

Добавить font-feature-settings для Inter:
```css
font-feature-settings: "ss01", "ss02", "cv01", "cv03";
```
Это активирует альтернативные глифы в Inter, делая текст заметно читабельнее.

#### Тени и глубина

Убрать подход "несколько плоских панелей с box-shadow". Заменить на:

```
Layer 0 (main bg):    0dp — никаких теней
Layer 1 (panels):     2dp — тень только снизу, мягкая
Layer 2 (tooltips):   8dp — лёгкое размытие + прозрачность
Layer 3 (modals):    16dp — glassmorphism с backdrop-blur
Layer 4 (menus):     24dp — чёткая, уверенная тень
```

## 4. Конкретные предложения по компонентам

### 4.1 Welcome Screen — полный редизайн

**Предлагаемая концепция: "Three-Section Hero"**

```
┌─────────────────────────────────────────────────────────────────┐
│  ● ─ ●                    notehub.md                           │
├──────────────┬──────────────────────────────────────────────────┤
│              │                                                  │
│  Pinned (2)  │   ┌──────────────────────────────────────────┐  │
│  ─────────── │   │  Думай чище.                             │  │
│  📓 Work     │   │  Пиши быстрее.                           │  │
│  📓 Personal │   │  Находи снова.                           │  │
│              │   └──────────────────────────────────────────┘  │
│  Recent (5)  │                                                  │
│  ─────────── │   [ Open Vault ]  [ Create Vault ]               │
│  > Notes     │                                                  │
│  > Research  │   ─────────────── или ──────────────────────    │
│  > Archive   │                                                  │
│  > Blog      │   Drag a folder here                            │
│  > Journal   │                                                  │
└──────────────┴──────────────────────────────────────────────────┘
```

**Изменения:**
- Левая панель делится на **Pinned** (max 3) и **Recent** (5-7) с разделителем
- Каждый vault в Recent показывает **относительное время** ("2 дня назад") и **количество файлов**
- Vault cards имеют hover preview — первые строки последнего открытого файла
- Правая секция: большой hero tagline, потом кнопки действий
- Drag & drop zone для открытия папок (drag folder here)
- Кнопка удаления из истории — **реализована** (не TODO)

### 4.2 Editor Layout — "Immersive Workspace"

**Убрать gap между панелями на desktop.** Вместо floating islands создать **один монолитный workspace** с разделителями:

```
┌──────────────────────────────────────────────────────────────┐
│ [icon] [icon] │ VAULT › folder › file.md          [⌘K] [⚙] │
├───────────────┼──────────────────────────────────────────────┤
│  📁 Notes     │  Tab1 × │ Tab2 × │ Tab3 ×         [+]       │
│  📁 Archive   ├──────────────────────────────────────────────┤
│  📄 Ideas.md  │                                              │
│  📄 Work.md   │           (Editor content)                   │
│               │                                              │
├───────────────┤                                              │
│               │                                              │
│  [Plugins]    │                                              │
│  [Settings]   ├──────────────────────────────────────────────┤
│  [About]      │ Markdown · UTF-8 · 1,234 words · Line 45    │
└───────────────┴──────────────────────────────────────────────┘
```

**Конкретные изменения:**
1. **Убрать gap: `gap: ${gap}px`** между grid-областями. Панели примыкают друг к другу, разделены тонкой линией (1px `border-subtle`).
2. **Ribbon вырастает до 64px** и получает текстовые подписи в micro-формате (опционально, при наведении).
3. **Breadcrumb в заголовке editor** заменяет пустое пространство над табами.
4. **Command Bar** (`⌘K`) — постоянно видимый, в правом верхнем углу шапки.
5. **Status bar** встраивается в editor panel (как в VS Code) — не отдельный floating panel.
6. **Боковая панель (Sidebar)** получает нижнюю секцию для secondary actions (plugins, settings).

### 4.3 File Tree — "Knowledge Navigator"

1. **Переименовать "EXPLORER" → имя vault** (уже частично реализовано через `rootName`). Убрать uppercase.
2. **Высота строки: 24px → 28px** — на 4px больше, значительно улучшает читаемость.
3. **Поиск — collapsible.** По умолчанию скрыт. Появляется по кнопке лупы (уже есть) или `Ctrl+F` в explorer фокусе.
4. **Цветные иконки типов файлов:**
   - `.md` — purple dot или icon
   - `.png/.jpg` — green (image)
   - `.pdf` — red
   - Папки — синие (folder blue)
5. **Empty state с CTA:**
```
📄 Vault is empty

Create your first note to begin.
[ + New Note ]
```
6. **Hover actions на строке** — иконки "создать внутри" и "..." появляются при hover на папке, справа от имени.

### 4.4 TabBar — "Tab Rail"

1. **Indicator несохранённых изменений:** точка `●` перед именем файла.
2. **Empty state вместо `return null`:**
```
No open files — open a file from the explorer or ⌘O
```
3. **Кнопка `+`** в конце таббара для создания нового файла.
4. **Активный таб**: Использовать `border-b: 2px solid accent` вместо background change — это стандартный, хорошо читаемый паттерн.
5. **Иконки типов файлов** вместо универсального FileText.

### 4.5 Context Menu — "Refined Menu"

```css
/* Убрать solid fill hover */
.nh-context-menu-item:hover {
    background: rgba(var(--nh-accent-primary-rgb), 0.10);
    color: var(--nh-text-primary);
}

/* Активный/выбранный элемент */
.nh-context-menu-item--active {
    background: rgba(var(--nh-accent-primary-rgb), 0.18);
    color: var(--nh-accent-primary);
}
```

Дополнительно:
- Увеличить padding item: `8px 12px → 7px 14px`
- border-radius item: `4px → 6px`
- Добавить keyboard shortcuts справа (hotkey hint, как в Notion)
- Группы с разделителями получают `<span>` заголовок над группой

### 4.6 Floating Toolbar — "Smart Toolbar"

1. **Active state кнопок**: Bold подсвечена если selection содержит **bold** текст.
2. **Группировка декларативная:**
```js
const BUTTON_GROUPS = [
    [bold, italic, strikethrough, code],
    [link],
    [h1, h2, h3, quote, list],
];
```
3. **"Хвостик" (caret)** — треугольник 6px снизу, указывающий на выделение.
4. **Tooltip при hover** — `title` attribute заменить на кастомный tooltip компонент.
5. **AI action** кнопка в конце (если AI-плагин активен) — иконка sparkle.

### 4.7 Settings Modal — "Command Center"

1. **Поиск настроек** — input вверху sidebar с fuzzy matching по labels и descriptions.
2. **Live preview** для темы: при смене темы фон backdrop меняется мгновенно.
3. **Размер: 800×600 → max(90vw, 900px) × max(85vh, 600px)** — более адаптивно.
4. **Breadcrumb внутри**: `Settings > Appearance > Accent Color`.
5. **Recently changed** — секция вверху контента с последними изменёнными настройками.
6. **Анимация перехода между табами** — content fade-in вместо мгновенной смены.

## 6. Один принцип, который изменит всё

Если из всего отчёта реализовать только **одно изменение**, это должно быть:

> **Убрать `gap: 16px` между плавающими панелями в EditorLayout и заменить их единым монолитным workspace с тонкими разделителями.**

Это единственное изменение уберёт главный визуальный дискомфорт — "острова" интерфейса, плавающие в тёмном море пространства, которые создают ощущение фрагментации вместо цельного рабочего пространства. После этого изменения приложение сразу начнёт ощущаться "серьёзным инструментом".
